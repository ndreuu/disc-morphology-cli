# Disc Morphology CLI

Папка DICOM → автоматическая кандидатная маска → **B, D, H, D/B** → локальная вебстраница с ползунками срезов и объяснением геометрической гипотезы.

```sh
disc-morphology analyze /path/to/dicom --output ./runs/study-01
```

После завершения открывается `report.html` в браузере. Снимки, контуры, расчёты, стили и код встроены в один файл: готовый отчёт можно перенести на другой компьютер и открыть без сервера и интернета. Снимки обрабатываются локально.

Это самостоятельный репозиторий: код не импортирует `mri-root-impact-ai`, не требует старых RSNA manifest/localizer и не ограничен сохранённым примером L3–L4.

## Установка и первый запуск

Python **3.10–3.12**, Git, macOS или Linux. Для нейросетей нужен отдельный runtime; CPU поддерживается. Первичная установка скачивает около 700 МБ архивов весов и зависимости PyTorch/nnU-Net, потребляет несколько ГБ диска. GPU CUDA можно выбрать явно.

```sh
git clone https://github.com/ndreuu/disc-morphology-cli.git
cd disc-morphology-cli
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install .

# Один раз: официальный код и четыре набора весов SpineSegPlus.
disc-morphology setup

# Каждый новый анализ: исходная папка DICOM, новый каталог результата.
disc-morphology analyze /path/to/dicom --output ./runs/study-01
```

По умолчанию модели сохраняются в `~/.cache/disc-morphology/spinesegplus`. Если в рабочем каталоге уже настроен `.models/spinesegplus/config.json`, CLI использует этот локальный cache. Приоритетный каталог можно задать переменной `DISC_MORPHOLOGY_MODEL_HOME` либо одинаковым `--model-home /path/to/models` в `setup` и `analyze`. `setup` создаёт отдельное окружение моделей; не заменяет пакеты окружения CLI.

Для проверки интерфейса **без моделей и медицинских данных**:

```sh
disc-morphology demo --output ./runs/demo
```

В учебном отчёте есть протрузия и экструзия, по семь синтетических срезов в каждой плоскости. Расчёты выполняет тот же геометрический модуль. Это схемы с известной геометрией, не результаты на пациенте.

Уже собранный [учебный HTML-отчёт](examples/synthetic-report.html) включён в репозиторий: после клонирования его можно сразу открыть в браузере.

## Что видно в отчёте

- Выбор автоматически предложенного уровня L1–L2…L5–S1.
- Отдельные ползунки сагиттальных и аксиальных срезов; кнопки и стрелки клавиатуры на изображении.
- Исходные изображения, точный пиксельный контур без сглаживания, опорная линия и подписанные B/D/H.
- Увеличение области и миниобзор полного кадра.
- **Расчёты выбранного кадра**, включая численную подстановку в `D/B` и сравнение разницы B/D с разрешением.
- Отдельные геометрическая гипотеза и итоговый морфологический статус, ограничения и JSON-экспорт.

Нажатие на изображение или выбор плоскости переключает источник чисел. Ползунок меняет срез и соответствующие ему измерения. Переключение слоёв влияет только на отображение.

При открытии выбирается срез с доступными численными оценками, если они есть. Это выбор начального вида, а не подтверждение пригодности маски: причины неопределённости остаются видны. Итоговая гипотеза хранится отдельно и относится к представительным кадрам с максимальным числом масочных пикселей.

## B, D, H и правило формы

Это геометрия **кандидатной маски относительно приближённой опорной линии**:

| Параметр | Вычисление |
|---|---|
| **B** | Длина связного пересечения маски с опорной линией |
| **D** | Максимальная связная хорда, параллельная B, за первой полосой разрешения |
| **H** | Наибольшее перпендикулярное расстояние наружной части маски от опорной линии |
| **D/B** | Ширина наружной части / ширина основания |

Координаты переводятся в физические миллиметры по DICOM, с учётом неравного размера пикселей и ориентации. Маска рассматривается как объединение пиксельных ячеек.

- `D − B > 2u` хотя бы в одной пригодной плоскости → геометрическая гипотеза **экструзии**.
- `B − D > 2u` в обеих пригодных независимых плоскостях → геометрическая гипотеза **протрузии**.
- Пограничные размеры или непригодные данные → **неопределённо**.

`u` не меньше диагонали native-пикселя; дополнительно учитывается разброс опорных точек, а для переноса маски — исходный межсрезовый шаг. Это нижняя оценка неопределённости, а не полная ошибка нейросети. `2u` — защитное правило прототипа, не клинически валидированный порог. **Правил «до 3/5 мм — протрузия, больше — грыжа» нет. H не определяет тип.**

Протрузия и экструзия обе относятся к грыжам. Параллельная хорда D — вычислительное приближение, не полная реализация максимального размера во всех направлениях и критериев [Fardon et al., 2014](https://radiology.queensu.ca/source/Lumbar_Disc_Nomenclature.pdf).

## Как запускаются модели

1. CLI находит DICOM-серии, выбирает T2 по описанию/времени эха и проверяет физическую геометрию.
2. Сагиттальная серия преобразуется в NIfTI с DICOM LPS → RAS affine. Для неоднозначного выбора требуется явный UID; масштаб из скриншота не угадывается.
3. **TotalSpineSeg Dataset101/102** сегментирует анатомию; **SpineSegPlus Dataset105** автоматически выбирает поисковые участки, **Dataset107** выдаёт бинарную LDH-маску. Ручные рамки или точки не нужны.
4. Кандидатные воксели автоматически относятся к ближайшему центру диска. По задним точкам соседних тел позвонков у замыкательных пластинок строится приближённая плоскость отсчёта. Маска кандидата не выбирает эти точки.
5. Маска переносится на исходные кадры, все доступные покадровые B/D/H/R сохраняются. Представительный кадр каждой плоскости выбирается по числу пикселей маски.
6. Формируется самостоятельный HTML. В браузере нейросеть не запускается.

Источник и веса закреплены по commit/SHA-256; inference выполняется отдельным Python-процессом. Исходный checkpoint загружается только через `weights_only=True` с узким NumPy allowlist; из производной копии удаляется training state, каждый тензор проверяется через `torch.equal`. Последующий inference использует `weights_only=True` без дополнительного allowlist. Подробности: [модели и ограничения](docs/models.md).

## Входные серии и полезные команды

Посмотреть серии без запуска нейросетей:

```sh
disc-morphology inspect /path/to/dicom
```

Если найдено несколько T2 или недостаточно контрастных метаданных:

```sh
disc-morphology analyze /path/to/dicom -o ./runs/study-02 \
  --sagittal-series 1.2.840.EXAMPLE.SAG \
  --axial-series 1.2.840.EXAMPLE.AX
```

Это выбор **серий**, не ручная разметка грыжи. Поддерживаются обычные однофреймовые grayscale MR DICOM. JPEG/PNG без геометрии, enhanced/multiframe DICOM, нерегулярный шаг и несовместимая геометрия дают явную ошибку. При отсутствии аксиальной серии доступен сагиттальный просмотр с ограничениями.

Если анонимизированный MR-набор не содержит тега `Modality`, его происхождение можно явно указать флагом `--allow-missing-modality`. Межсерийный перенос при разных/пропущенных `FrameOfReferenceUID` по умолчанию блокируется; аксиальные снимки при этом доступны. Для исследовательского показа переноса есть **`--allow-unverified-registration`**. Этот флаг не подтверждает регистрацию.

```sh
# Без автоматического открытия браузера; stdout содержит пути JSON.
disc-morphology analyze /path/to/dicom -o ./runs/study-03 --no-open

# CUDA и ограничение числа CPU-потоков.
disc-morphology analyze /path/to/dicom -o ./runs/study-04 --device cuda --threads 2

# Уже полученные внешние NIfTI-маски: геометрия без нового inference.
disc-morphology analyze /path/to/dicom -o ./runs/from-masks \
  --candidate candidate.nii.gz --anatomy totalspineseg-labels.nii.gz

# Проверка SHA исходников, масок и результата без inference.
disc-morphology verify ./runs/study-03
```

Режим внешних масок требует правильно согласованных физических NIfTI RAS-координат. Принадлежность произвольной маски пациенту/исследованию автоматически не подтверждается. В отчёте этот режим явно отличается от запуска моделей.

`--timeout` задаёт предел длительности inference в секундах, по умолчанию 3600. Существующие каталоги результата не перезаписываются. Ошибка оставляет `error.json` и журналы; незавершённый запуск не выдаёт успешный отчёт.

## Файлы результата

```text
study-01/
  report.html       # Самостоятельный просмотрщик: открывается двойным кликом
  result.json       # Изображения, контуры, числа и причины неопределённости
  run.json          # Локальные пути и SHA источников/выходов
  model_input/     # Сагиттальная серия в NIfTI
  segmentation/   # Фактический выход моделей
  inference.log    # Журнал моделей
```

`run.json` нужен только для локальной проверки целостности; готовый HTML работает самостоятельно. `verify` проверяет соответствие сохранённому SHA inventory, не клиническую точность и не повторяет нейросетевой запуск.

## Текущее покрытие

Работают автоматический запуск сегментатора, приближённый референс, покадровые измерения и объяснение гипотезы. **Аксиальный контур пока является переносом сагиттальной маски, не независимой аксиальной сегментацией.** Поэтому клинический тип остаётся `indeterminate`; гипотеза и кандидатные числа показываются отдельно. Отсутствующая маска не означает отсутствия грыжи.

Точность границы дискового пространства и устойчивость сегментации не подтверждены врачебной разметкой. Полная многосрезовая морфология, bulge, миграция, секвестрация и корешковая компрессия не определяются. Проверка пяти уровней исследовательская: авторский default — L4–L5/L5–S1; покрытие весами верхних трёх уровней не подтверждено. Это не готовая семиклассовая диагностическая система.

## Разработка и проверки

```sh
python -m pip install -e .
python -m unittest discover -s tests -v
node --check src/disc_morphology/assets/report.js
disc-morphology demo --output ./runs/check --no-open
```

Тесты используют только синтетические DICOM и маски. Веса и медицинские снимки в Git не входят. Геометрическое ядро перенесено из собственного исследовательского прототипа MRI Root Impact AI; внешний модельный код остаётся отдельной зависимостью.

[Фактическая проверка версии 0.1.0](docs/validation.md): установка пакета, 44 теста, CI Python 3.10/3.12, полный CPU-запуск на исходных DICOM и браузерная проверка. В локальном тестировании модельного процесса наблюдался пик памяти около 17 ГБ.
